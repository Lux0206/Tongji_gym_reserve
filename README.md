# 同济场馆空位提醒（多场馆只读版）

覆盖 **羽毛球 / 乒乓球 / 网球** 三类运动、**四平 / 嘉定 / 沪西** 三个校区的 8 个场馆。
只做查询和提醒，**没有任何下单/支付功能**。
仅作为学习交流使用，不确定是否有风险，不承担任何风险。

## 一、启动

双击 `启动网页.bat`，或运行：

```bash
python webapp.py
```

打开 <http://127.0.0.1:5000>。

默认状态：**暂停 + 0 个场馆启用**。此时不会登录、不扫描、不查空位。
未勾选的场馆**不会发任何请求**。

## 三、使用步骤

1. 在「场馆管理」里勾选要跟踪的场馆（可多选）。
2. 每个场馆单独设置：
   - 扫描间隔（默认 30 分钟，最小 15 分钟）
   - 监控天数（今天 + N 天，N=1~7，默认 7）
   - 时段偏好（不选 = 不限）
   - 场地偏好（不选 = 不限；首次扫描后自动获取场地列表）
3. 点「保存场馆设置」。
4. 确认账号状态后，点右上角「恢复」。
5. 首页「跟踪的场馆」会显示每个场馆的空位摘要、上次/下次扫描；点「查看空位」看明细。

## 四、频率与请求控制

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| 每场馆间隔 | 30 分钟 | 最小 15 分钟，带 ±20% 随机抖动 |
| 运行时段 | 07:00~22:00 | 夜间不读取 |
| 每小时请求上限 | 60 次 | 所有场馆共用；超出自动延后 |
| 监控天数 | 今天 + 7 天 | 可选 N=1~7；12:00 后共 N+1 个日期 |
| 扫描方式 | 先查日期，跳过全满日期 | 每场馆每轮通常 2~8 次请求 |

**实际间隔会被请求上限拉长**：例如 8 个场馆都设 15 分钟，理论需求远超 60 次/小时，系统会自动排队，每个场馆实际可能 1 小时才轮到一次。首页会显示真实的“下次扫描”时间。

### 新放号时的提示规则

- 每天 12:00 新放号时，第一次读取只建立基线，**不推送提醒**；
- 下一次读取（第二次）才按你设置的场馆/时段/场地偏好提示空缺位置；
- 不额外做 12:00 专用扫描，仍按各场馆正常间隔进行。

## 五、提醒

- 只报「已约满/未开放 → 空闲」的变化，合并成一封邮件；
- 邮件标题带场馆名和校区；
- 每场馆独立偏好过滤；
- 额度满时仍提醒：开启后额度已满/有未支付订单时仍提醒空位（方便让搭子抢）；关闭则额度满时暂停提醒；
- 支持 QQ 邮箱 SMTP、企业微信机器人 / 通用 Webhook；
- 本地提示音可选，默认关。

## 六、明确没有的功能

- ❌ 下单（`ConfirmOrder`）
- ❌ 支付 / 0 元支付
- ❌ 滑块验证码识别
- ❌ 自动抢 / 抢约窗口
- ❌ 两单连约

`api_client.py` 只保留登录和查询，底层 `_form`/`_json` 带 URL 白名单；`core.py` 没有 `book`；`monitor.py` 没有自动抢。
旧的 `grab.py`、`grabber.py`、`calib_solve.py`、旧配置已移到 `archive/`，运行目录不会导入。

## 七、邮箱设置（QQ 邮箱）

1. QQ 邮箱网页版 → 设置 → 账户 → 开启「POP3/SMTP 服务」
2. 生成**授权码**（不是 QQ 登录密码）
3. 网页 → 邮箱：`smtp.qq.com`、端口 `465`、勾选 SSL，填发件邮箱和授权码
4. 点「发送测试邮件」，检查收件箱和垃圾箱

## 八、文件说明

| 文件 | 作用 |
| --- | --- |
| `webapp.py` | 网页服务 + 多场馆调度（只读） |
| `venues.py` | 8 个场馆目录 |
| `store.py` | SQLite：设置、按场馆快照、提醒、规律、日志 |
| `api_client.py` | 只读客户端：登录 + 查询，带 URL 白名单 |
| `core.py` | 会话、按场馆扫描、额度查询（仅用于邮件额度提示，无下单） |
| `monitor.py` | 按场馆差异检测、偏好过滤、邮件提醒（无自动抢） |
| `notify.py` | SMTP 邮件 / Webhook |

## 九、注意事项

- 网页只绑定 `127.0.0.1`，只有本机能访问
- `data.db` 里是明文账号密码和邮箱授权码，注意保管
- 电脑关机/休眠时无法监控；可在网页里打开「阻止睡眠」
- 邮件可能进垃圾箱；QQ 邮箱有发送频率限制
- 账号刚解封，建议先保持低频率（30 分钟以上）、白天运行，观察几天
